# 安全规范

## 认证安全

### 密码存储

- 所有密码使用 **bcrypt** 哈希存储，salt rounds 默认 10
- 密码明文永远不会存储或记录
- 密码长度限制：6-50 个字符

### JWT 令牌

- JWT 使用 HMAC-SHA256 签名
- 默认有效期 7 天，可通过 `JWT_EXPIRES_IN` 环境变量调整
- 令牌存储在 cookie（httpOnly）和 localStorage（方便 iframe 使用）
- 建议在生产环境中仅使用 httpOnly cookie

### 代理登录安全

1. **HMAC-SHA256 签名**：proxyToken 使用应用的 secret 进行签名验证
2. **Nonce 防重放**：每个 proxyToken 必须包含唯一的 nonce，使用后即标记
3. **时间限制**：proxyToken 可设置过期时间（exp），建议不超过 5 分钟
4. **Secret 管理**：secret 仅在后端和第三方应用之间使用，不暴露给前端

## 内容安全

### XSS 防护

- 所有用户输入通过 **DOMPurify** 进行 HTML 清洗
- 仅允许安全的 HTML 标签：`b`, `i`, `em`, `strong`, `a`, `p`, `br`, `ul`, `ol`, `li`, `code`, `pre`, `blockquote`
- 评论内容最大长度 1024 字符

### CSP 策略

- 嵌入页面 `/embed` 设置 `Content-Security-Policy: frame-ancestors *`，允许任意域名嵌入
- 建议在生产环境中限制为特定的允许域名

## 频率限制

### 评论频率

- 每个用户/IP 每分钟最多发送 **5 条**评论
- 可通过 `RATE_LIMIT_PER_MINUTE` 环境变量调整
- 超出限制返回 HTTP 429

### CORS 动态配置

- 在应用管理后台可为每个应用配置允许的域名
- 支持通配符（如 `*.example.com`）
- 未配置时默认允许所有来源（开发阶段）

## 数据库安全

- 使用 MySQL 数据库，Prisma ORM 自带参数化查询，防止 SQL 注入
- 数据库连接信息通过环境变量配置，不硬编码
- 新增表（apps、third_party_users、nonces）与原有表共存，不影响已有数据

## 部署建议

1. **使用 HTTPS**：所有通信必须通过 HTTPS
2. **更换默认 Secret**：务必修改 `JWT_SECRET` 环境变量
3. **限制管理后台访问**：通过反向代理（Nginx）限制 `/admin/*` 的访问 IP
4. **定期备份 MySQL 数据库**
5. **监控日志**：关注异常登录和大量评论请求
6. **更新依赖**：定期更新 npm 依赖，修复安全漏洞
